## 调研与候选方案（TE-4a）

调研日期 2026-10-13。标注约定：**[源]** 有可点击来源；**[实测]** 本次只读探测（OpenRouter 公开模型列表、本地算术）；**[推测]** 无来源或来源不足，必须由 TE-4b 验证。没有任何结论来自用户真实会话；所有费用/时延为估算，未跑模型。

### 0. 结论先行

1. **没有同类产品对“语义自动选会话”有先例。** 所有被查产品都是“搜索/排序 + 人选”，只有确定性规则（最近一个、精确名称匹配）才会自动选。Jev 的自动送达在业界是新做法，A1 风险证据只能来自我们自己的评测。
2. **“留出集自动决策 ≥300 且 A1=0”不是一个能证明低风险的门槛，只是一个必要条件。** 零事件时 95% 上界是 0.99%（n=300）；若真实 A1 率为 0.3%，通过概率仅 41%，为 0.1% 才有 74%（见 §2.3）。验收要同时报告 Clopper-Pearson 上界，并把“上线后先确认再放开”作为兜底（见 §9）。
3. **召回要用并集而不是单一分数。** “继续”“那个再改一下”这类短句没有词面信号，只能靠语境先验（上一句去处、前台会话、存活、最近活跃）；FTS/向量只负责有内容的句子。把语境候选强制并入候选集，才不会因为召回漏掉而被迫送错（§4）。
4. **单一置信信号不可靠。** 口头概率过度自信、一致性在强模型上会“一致地错”，Jev 的 confidence 是分布集中度而不是正确率。闸门应由多个相互独立的信号做“且”运算，阈值在开发集上按单侧二项上界选，留出集只验证（§2、§3）。
5. **Jev 的硬约束：** 单个 Choice 最多 255 项，请求总计 64k、state+最长问题 ≤32k，文档自陈“无关内容会降低准确率”“选项顺序偏向靠前项”“state 被当作可信输入”。所以 Jev 只能吃召回后的 ≤~60 张卡，不能吃全部 2000 张；对卡片内容里的注入没有防护，路由必须把卡片当不可信数据，且不让模型输出直接触发写入（§3.3、§7）。

### 2. 选择性预测/弃权与统计保证（D7）

#### 2.1 方法谱系

- **Selective classification / risk-coverage**：固定目标风险，最大化覆盖。Geifman & El-Yaniv 的 SGR 在已训练分类器上对置信函数排序，二分搜索阈值，用二项上界加 δ/k 的并集修正，以概率 ≥1-δ 保证选择风险 ≤ r*；ImageNet top-5 上 2% 风险、99.9% 置信度下覆盖近 60% [源](https://arxiv.org/abs/1705.08500)。**这正是我们的设定**（A1 率上界 + 最大自动覆盖）。
- **Learn then Test (LTT)**：把风险控制写成多重假设检验，对任意模型、有限样本给出严格的风险保证，不需要重训 [源](https://arxiv.org/abs/2110.01052)。可用来在多个旋钮（Jev 概率阈值、margin、一致性要求）上联合选参并保证 FWER。
- **Conformal Risk Control (CRC)**：控制任意单调损失的**期望**，有 O(1/n) 的紧性 [源](https://arxiv.org/abs/2208.02814)。注意它是期望意义，不是“以高概率 A1=0”，对 A1 这种近零事件不如 SGR/LTT 贴切。
- **共形预测集用于 LLM 选择题**：Kumar 等发现预测集大小与正确率强相关，**单元素预测集的准确率显著高于朴素 top-1** [源](https://arxiv.org/abs/2305.18404)。可作为“自动”的条件：保形集只含一个候选才自动，否则澄清。
- **弃权综述与评测陷阱**：弃权的查询/模型/价值观三视角见 [Know Your Limits](https://arxiv.org/abs/2407.18418)；选择性分类评测里指标插值、排序方式会改变结论，建议用 AUGRC 之类的无插值指标 [源](https://proceedings.neurips.cc/paper_files/paper/2024/file/047c84ec50bd8ea29349b996fc64af4b-Paper-Conference.pdf)。LLM 置信度评测同样发现 AUARC 的线性/阶梯插值会反转方法排名 [源](https://arxiv.org/abs/2608.04899)。我们的主指标直接用“自动决策中的 A1 数 + CP 上界”，风险-覆盖曲线只作辅助且用阶梯式。

#### 2.2 对开发集定阈值的做法（建议）

1. 开发集按置信信号从高到低排序，扫描 k 个候选阈值；每个阈值计算“自动子集中 A1 数”的单侧 Clopper-Pearson 上界，用 δ/k（Bonferroni，SGR 做法）或 LTT 的固定序列检验；选**覆盖最大且上界 ≤ 目标**的阈值。
2. 目标取小于验收口径，使留出集通过概率够高（见 2.3）：例如开发集上界 ≤0.5%。
3. 留出集只跑一次，只做验证；同时报告 CP 上界。

#### 2.3 样本量与“300 且 0”的含义 **[实测，本地二项算术]**

零/少量错误时，单侧 95% Clopper-Pearson 上界：

| 自动决策数 n | 0 个 A1 | 1 个 | 2 个 |
| --- | --- | --- | --- |
| 100 | 2.95% | 4.66% | 6.16% |
| 300 | 0.99% | 1.57% | 2.08% |
| 500 | 0.60% | 0.95% | 1.25% |
| 1000 | 0.30% | 0.47% | 0.63% |
| 2000 | 0.15% | 0.24% | 0.31% |

要使上界 ≤1% / 0.5% / 0.3% / 0.1%，零事件分别需 299 / 598 / 998 / 2995 个自动决策。规则三的来源见 [Hanley & Lippman-Hand 1983](https://jhanley.biostat.mcgill.ca/c607/ch08/zero_numerator.pdf)。

“在 300 个自动决策里观察到 0 个 A1”的通过概率 = (1-r)^300：真实 A1 率 1% → 4.9%；0.5% → 22%；0.3% → 41%；0.1% → 74%；0.05% → 86%。**所以：通过门槛说明真实率大概率 ≲0.3%，但不能证明 ≤0.1%；若要求真实率 ≤0.3%（95% 置信），留出集需约 1000 个自动决策，按 60% 覆盖需约 1700 条留出查询。** 本机历史量（Claude 默认保留 30 天，最早 2026-09-13）可能不足，TE-3 需先数出可挖掘的续接例总数。

另两点会让名义样本量虚高：①同一会话内的多条查询相关，**有效样本数更接近“不同会话数”**，建议按会话聚簇计 CP 上界或做聚簇 bootstrap；②自动挖掘的标签有噪声（用户当时的去处不一定是唯一合理去处，如重复会话），**每个与标签不一致的自动决策必须人工裁决**，才能区分 A1 与标签错误。

### 3. LLM 置信度校准（D5）

#### 3.1 各类信号的已知性质

| 信号 | 已知结论 | 来源 |
| --- | --- | --- |
| 口头置信度 | 倾向过度自信；GPT-4 平均 AUROC 仅约 62.7%（接近随机）；论文以 AUROC<0.6 视为显著偏离 | [Xiong et al., ICLR 2024](https://arxiv.org/abs/2306.13063) |
| 口头置信度 vs 条件概率（RLHF 模型） | 口头置信度通常比 RLHF 模型的 token 概率校准得更好，ECE 常降约一半；先给多个候选再给置信度更好 | [Tian et al., EMNLP 2023](https://arxiv.org/abs/2305.14975) |
| 口头置信度的稀疏性 | Qwen3-32B 在 SST-2 上只输出 8 个不同置信值，过半恰为 95%；用 token 概率对数字加权可略改善（AUARC +2.3） | [arXiv 2608.04899](https://arxiv.org/abs/2608.04899)（摘要级，未读全文） |
| P(True)/P(IK) | 大模型在合适格式下校准较好；零样本自评 P(True) 校准差，随规模改善 | [Kadavath et al.](https://arxiv.org/abs/2207.05221) |
| 多次采样一致性 | 多次采样的一致性类方法显著优于单次口头置信度（该文平均 AUROC 约 73.0 vs 56.4，据搜索摘要，**未核对全文**）；一致性可作为“弱模型是否可信”的难度信号 | [Xiong](https://arxiv.org/abs/2306.13063)；[Yue et al., ICLR 2024](https://arxiv.org/abs/2310.03094) |
| 一致 ≠ 正确 | GPQA/AIME 上自一致和跨模型一致只是弱代理（ρ 0.20–0.59）；前沿模型“一致地错”：一致度≥0.8 的条目里 48% 错 | [arXiv 2607.08065](https://arxiv.org/abs/2607.08065)（摘要级） |
| 顺序/选项偏置 | LLM 有“选项 ID token 偏置”，提示工程无法消除；PriDe 用少量置换估计先验去偏 | [Zheng et al., ICLR 2024](https://arxiv.org/abs/2309.03882) |
| 评审位置偏置 | GPT-4 偏好第一个、ChatGPT 偏好第二个；建议多顺序平衡聚合，分歧大的样本交人 | [Wang et al., ACL 2024](https://arxiv.org/abs/2305.17926) |
| 内容无关先验 | 用无内容输入（如 “N/A”）估计偏置并校正 | [Zhao et al., ICML 2021](https://arxiv.org/abs/2102.09690) |
| 长上下文位置效应 | 相关信息在上下文中间时性能显著下降 | [Liu et al.](https://arxiv.org/abs/2307.03172) |

**综合判断（[推测]，由 D5 证伪）：** 文献里没有一种信号在“分类/选择”任务上稳定占优；强模型的一致性会高估，口头概率会稀疏过度自信。因此不押单一信号，用“置换稳定 ∧ 多模型一致 ∧ Jev 分布 ∧ 确定性证据”的合取，并以开发集 AUROC / 阶梯式风险-覆盖逐一核验增量。采样一致性对 Jev 不可用（分布输出确定，非采样；**[推测]** 重复调用结果应近似相同，需 D5 测一次），对通用模型可用“选项顺序置换”替代随机采样，同时覆盖位置偏置。

#### 3.2 OpenRouter Decisions（Jev）返回的概率性质 **[源]**

- 每个选项给出概率，和为 1；Choice 最多 255 项；文档没有说明概率如何产生、是否校准、顺序偏置（[Choice](https://docs.typesafe.ai/primitives/choice)）。
- `confidence` = (p_max − 1/n) / (1 − 1/n)，衡量分布集中度，“不是答案正确的概率”；官方三档建议：>0.9 自动，<0.5 转人，不同后果的动作应设不同阈值（[Confidence](https://docs.typesafe.ai/confidence)）。候选很多时 1/n→0，confidence≈p_max。
- 当前生产阈值 p≥0.85 且与第二名差 ≥0.20（`src/router/jev.ts`，用户 2026-09-28 裁定）**比官方“>0.9 自动”更松**。这不是 bug，但意味着闸门风险必须靠评测而非官方背书（事实陈述，不推翻用户裁定）。
- 已知限制：无关内容降低准确率（context rot）；选项顺序偏向靠前项；不把 state 当对抗输入，被注入指令可移动答案；不擅长日期比较、计数、多跳（[Jev 1.13 限制](https://docs.typesafe.ai/model-jaggedness/jev-1.13)）。官方称英文最佳、中文需单独验证（[研究 §2](jev-2026-09-21.md)）。
- 价格 $0.042/百万输入 token，输出免费；上下文 64k（[OpenRouter 页面](https://openrouter.ai/typesafe/jev-1.13/api)）。OpenRouter 请求支持 `sessionId`/`trace`/`user`（[SDK 文档](https://github.com/OpenRouterTeam/typescript-sdk/blob/main/docs/models/decisionsrequest.mdx)）。
- 已有本仓证据：12 条合成中文开发样例 12/12，p50 1306.73 ms、p95 1478.82 ms，总费 $0.000345534；未做封存评测（[实验 README §6](../experiments/native-task-routing-lab/README.md)）。**不能外推到 2000 会话/大 state/真实口语。**

#### 3.3 对 Jev 的两条设计推论

- 候选顺序要随机化/置换并核对稳定性（文档承认偏向靠前项）；固定按相关度排序等于把召回排名泄漏进决策偏置，反而可能放大“召回第一名”的偏好。
- 卡片文本（标题、首句、最后回复）来自历史会话，含工具输出，**是不可信输入**（间接注入：[Greshake et al.](https://arxiv.org/abs/2302.12173)）。已有的“指令不得修改规则”提示不是防护；防护应在代码侧：模型只能输出候选 ID，闸门由确定性规则复核，输出不触发其他动作。

| LLM 重排 | RankGPT：listwise 排列生成 + 滑动窗口，GPT-4 达到或超过监督重排，但对初始顺序敏感 | [Sun et al., EMNLP 2023](https://arxiv.org/abs/2304.09542) |
| 全部卡片直接给长上下文模型 | 资源足够时长上下文优于 RAG（最多 +13.1%），RAG 成本更低；二者可用“自省路由”混合 | [Li et al., EMNLP 2024 industry](https://arxiv.org/abs/2407.16833)；位置效应见 [Lost in the Middle](https://arxiv.org/abs/2307.03172) |

**召回设计建议：** 候选集 = 词面通道（FTS trigram + 双字补充）top-k ∪ 稠密通道 top-k（RRF 融合）∪ **语境通道（强制并入）**：上一句去处、唤起前前台会话、全部存活会话、最近 N 个活跃会话、同 cwd 最近会话。语境通道不参与分数竞争，只保证“合理的上下文候选一定在场”。**因为错误 A1 常发生在“正确答案不在候选里而模型被迫在剩余里选”**，必须保留 NEW/CLARIFY 作为一等选项并度量“正确答案不在候选”时的行为（D1）。

### 5. 会话表示与短指代（D2）

- 现有产品的字段取舍：agsearch 以“标题/项目 > 首条提示 > 全文”加权（[源](https://github.com/devcodes9/agsearch)），Claude 选择器用名称/AI 标题/摘要/首句（[源](https://code.claude.com/docs/en/sessions)），Cursor/Warp 多仅标题（[源](https://forum.cursor.com/t/search-past-conversations-in-cursor-ai-chat-window/112703)）。**文献里没有找到专门比较“会话路由”卡片字段区分度的研究，各字段的相对价值是 [推测]，由 D2 消融测定。**
- 我们卡片已有字段：标题、首句、最近几句用户输入、最后回复、cwd、时间、轮数。消融建议的字段组：A 标题+cwd；B +首句；C +最近 3 句用户输入；D +最后回复；E +近期文件路径/标识符（来自工具调用，当前卡片没有，**候选新字段**）；F +会话级一句话摘要（生成成本，且摘要有损）。度量每组的 recall@k 与 A1-相当的“错选率”。**推测：**用户输入侧（首句+最近几句）区分度高于助手回复，因为助手回复长而泛；文件路径对“同项目多会话”区分度最高。
- 短指代（“继续”“那个再改一下”）：对话式搜索把它们当作省略/指代消解问题，用 LLM 把当前句基于上文改写为独立查询（[CANARD](https://aclanthology.org/D19-1605/)）；LLM4CS 用多次改写+假想回答聚合表示用户的上下文意图，效果优于监督基线甚至人工改写（[Mao et al.](https://arxiv.org/abs/2303.06573)）。TopiOCQA 说明对话中话题切换会让依赖历史的检索显著变难（[源](https://arxiv.org/abs/2110.00768)）。
- 对我们的映射：短指代句的“上文”是入口里的上一句及其去处（`previous`）与唤起前前台会话，不是卡片。本仓已观察到的现象（[jev.ts 注释](../../src/router/jev.ts)）：带上上一句后承接追问从 0.66 判新话题变为 0.91 归原任务，说明语境进 state 有效；但这是单用户单例观察，不是统计结论。建议：纯短指代句（无实质名词，如长度≤N、命中指代词表）**默认只信语境通道**——有唯一的“上一句去处且在 T 分钟内”才允许自动，否则澄清；这一条是确定性规则，不依赖模型校准。阈值 N、T 由 D6/D8 在开发集定，不预设。

### 8. 候选方案（每个 = 召回 + 表示 + 决策模型 + 置信信号 + 闸门）

下列费用为估算（价格来自 §4/§6 的 2026-10-13 列表，token 体量按 §4），时延为**未测的推测**，除非标注“已测”。统一前提：①候选集一律包含 NEW/CLARIFY；②闸门之外还有 §3.3 的“模型只能选 ID”和不可恢复会话的代码硬过滤。

**方案 P1 — Jev 单模型 + 语境并集（对当前生产的加固版，基线）**
- 召回：词面+稠密 RRF top-30 ∪ 语境通道，总计 ≤60 卡，顺序随机。
- 表示：标题、cwd、首句 ≤200 字、最近 3 句用户输入、最后回复 ≤200 字（Jev 单卡 ≤~120 token）。
- 决策模型：`typesafe/jev-1.13`。
- 置信信号：Jev 的 p_max 与第二名差；对 2 个不同顺序各调一次，要求同选。
- 闸门：p_max≥θ ∧ margin≥m ∧ 两顺序一致 ∧ 非纯指代句（纯指代句仅在“上一句去处且 ≤T 分钟”时放行）。θ、m、T 在开发集按 §2.2 定。
- 理由：最便宜、最快，是现有投入的延伸，也是其余方案的对照基线。
- 预期 A1 来源：Jev 中文/口语校准不足；同项目近似会话；顺序偏置；卡片注入；召回漏掉正确答案后在剩余里“较确定地”选错。
- 费用/时延：≈$0.0002–0.0005/次；p50≈1.3 s、p95≈1.5–2.5 s（小样本已测 p50 1.31 s / p95 1.48 s，大 state 未测，推测 p95 ≲2.5 s）。
- TE-4b 证伪：D1（答案不在库）、D3（召回@60 是否 ≥99%）、D4（Jev 在真实中文口语上的准确率）、D5（Jev 概率 AUROC 与双顺序一致增益）、D7（θ/m 下开发集上界）。

**方案 P2 — 双家族一致闸门（Jev + 通用快模型）**
- 召回：同 P1。
- 表示：同 P1，另给通用模型更长的最近输入（它支持更长上下文）。
- 决策模型：Jev + `deepseek/deepseek-v4.1-flash` 或 `anthropic/claude-haiku-5.5`（二选一，D4 择优），后者用不同卡片顺序，要求输出选项与每项概率。
- 置信信号：Jev 分布；通用模型的选项 token 概率（DeepSeek/Qwen 有 logprobs）或口头概率；两模型选择一致；通用模型在两顺序上稳定。
- 闸门：Jev 过阈值 ∧ 通用模型同选且过其阈值 ∧ 顺序稳定 ∧ 同 P1 的指代规则。任一失败 → 澄清（前 3 取两模型概率并集排序）。
- 理由：A1 要求两个不同家族同时错到同一个候选，错误相关性低于单模型（但“一致地错”已被观察到，见 §3.1，所以不单靠它）。
- 预期 A1 来源：两模型共有的偏差（都偏最近活跃会话、都被同一注入欺骗）；覆盖下降 → B2 升高。
- 费用/时延：≈$0.0007–0.0015/次（并行，两顺序）；p95 推测 2–3.5 s（取最慢模型）。
- TE-4b 证伪：D4（家族相关性：两者同错占比）、D5（一致性相对单模型的 AUROC 增量与覆盖代价）、D8（对抗集）、D7。

**方案 P3 — 免召回：全部近期卡片 + 长上下文强模型 + 顺序置换**
- 召回：无；取近 N（300–1000）张紧凑卡片（每张 60–100 token），按最近活动分层，卡片库放 prompt 前缀以利用缓存。
- 表示：极紧凑（标题、cwd、首句 ≤80 字、最近 1–2 句）。
- 决策模型：`anthropic/claude-haiku-5.5` 起步，难例升 `claude-sonnet-5.5`；或 DeepSeek V4.1 Flash。
- 置信信号：2–3 个顺序（块级置换）下选择一致 + 口头概率/（DeepSeek）logprob。
- 闸门：三顺序一致 ∧ 概率≥θ ∧ 指代规则；否则澄清。
- 理由：消除召回漏答案这一整类 A1（模型看得到全部）；实现最简单。
- 预期 A1 来源：长上下文位置效应/漏看（[Lost in the Middle](https://arxiv.org/abs/2307.03172)）；卡片极紧凑导致区分度不足；缓存未命中时时延。
- 费用/时延：Haiku 30–80k token 未缓存 $0.003–0.008，缓存读后降一个数量级；三次并行 ≈$0.01–0.025（未缓存）；p95 推测 4–8 s（>3 s 目标，需缓存或降 N 才可能达标）。
- TE-4b 证伪：D3（对比召回方案，看召回损失与长上下文损失哪个大）、D4、D5、时延 p95。若时延不达标则该方案仅可作离线上界/对照，不作生产候选。

**方案 P4 — 召回 + 强模型选择 + 独立“反驳式”验证**
- 召回：同 P1，但 top-15 ∪ 语境通道，≤25 卡。
- 表示：较丰富（首句、最近 3 句、最后回复各 ≤300 字），因为卡少。
- 决策模型：第一步 `claude-sonnet-5.5`（或 `qwen3.8-max-0902`）选候选并给理由；第二步只带被选会话的卡片和另两个最强竞争者，用另一个家族（`gpt-5.6-luna` 或 Jev 的 Noul 命题）问“这句话明确属于该会话而不是竞争者吗/应否新建”，要求给出反驳证据。
- 置信信号：两步同向；验证命题概率；竞争者是否被明确排除。
- 闸门：选择 ∧ 验证通过 ∧ 无同 cwd 近似竞争者概率 >ε。
- 理由：把“选”和“证伪”分开，针对最危险的错误（近似会话、本该新建）。
- 预期 A1 来源：强模型对“理由”的自洽偏差（会为错选编出合理理由）；两步串联时延；成本。
- 费用/时延：≈$0.01–0.015/次（Sonnet 5k 输入+300 输出约 $0.013，验证步 ≈$0.0005）；p95 推测 5–9 s（串行两次，不达 3 s 目标）。
- TE-4b 证伪：D4（强模型相对 Jev/快模型准确率提升是否值 20–50 倍成本）、D5（验证步的 AUROC 增量）、D8；若不优于 P2，则放弃。

**方案 P5 — 确定性证据优先（保守下限）**
- 召回：同 P1。
- 表示：同 P1，另增“可核对证据”特征：命中的唯一文件路径/标识符/项目名、是否为存活会话、是否为上一句去处且在 T 分钟内、是否为唤起前前台会话。
- 决策模型：Jev 或 Haiku 5.5 仅负责排序 top-3；自动与否由规则决定。
- 置信信号：规则命中（离散，可审计）+ 模型 top-1 与规则一致。
- 闸门：仅当（a）存在唯一强证据（唯一命中的路径/标识符，或上一句去处 ≤T 分钟且为指代句，或前台会话且句子为指代）且（b）模型 top-1 与之一致，才自动；其余一律澄清。
- 理由：A1 风险最低、可解释、可逐条审计；也是“上线前期”的安全默认。
- 预期 A1 来源：规则本身的假阳性（例如前台会话其实是用户正想离开的会话）；覆盖低导致 B2 高（可能 <40%，**推测**）。
- 费用/时延：≈$0.0002–0.0005/次；p95 ≲2.5 s。
- TE-4b 证伪：D6（语境先验有/无对比，直接度量每条规则的精度和覆盖）、D7、B2 覆盖是否 ≥60%（若不到，说明需要模型信号补充，转 P2）。

**组合提示：** P5 的规则可作为任何方案的“且”条件（先天更安全），P2 的跨家族一致可作为 P1/P5 的附加条件。最终推荐可能是 P5∧P2 的组合，而不是单个方案——由 D5/D7 按覆盖与上界决定。

### 9. 推荐、实验顺序与样本量

**推荐：** 以 **P1 为基线，朝“P5 规则 ∧ P2 跨家族一致”收敛**。理由：①成本和时延都在 3 秒目标内（P3/P4 大概率不达标）；②A1 的最大来源是近似会话与短指代，规则+多模型一致比单模型阈值更能直接压制；③全部可审计；④强模型（P4）的边际收益需要单独证明。P3 只作上界对照。

**实验顺序（对应 D1–D8）：**
1. **E0 数据体检（D1，$0）：**统计可挖掘续接例总数、不同会话数、正确答案不在库比例（保留期、归档、非交互过滤）。先决定 §2.3 的统计功效是否够用；总量不足就不要承诺“≥300 自动”的可证性。
2. **E1 召回（D3，≈$0.05）：**FTS trigram、双字、BGE-M3/Qwen3-Embedding、RRF、语境并集的 recall@{10,30,60}，不调用决策模型。目标：并集 recall@60 ≥99%（答案不在候选里是不可挽回的 A1/B1 来源）。
3. **E2 表示消融（D2）：**在固定召回 + 固定快模型上做 §5 的 A–F 字段组，选最小有效字段集（也降低注入面和 token 成本）。
4. **E3 模型对比（D4）：**6 个模型、同一候选集、2 个顺序，记录准确率、各自“名义自动”下的 A1、时延、费用、中文口语分层结果。
5. **E4 置信信号（D5）：**以“是否选对”为标签算 AUROC 与阶梯式风险-覆盖：Jev p_max/margin、通用模型 logprob/口头概率、顺序稳定、跨模型一致、规则命中，及其合取。
6. **E5 语境与对抗（D6、D8）：**语境信号有/无对比；对抗集（同项目、换话题、跨工具、纯指代、注入）单列。
7. **E6 闸门定阈（D7）：**在开发集上按 §2.2 选参，冻结方案与参数版本，留出集一次性验收。

### 10. 最大不确定点

1. **标签质量与可用样本量**：自动挖掘的“真实去处”有噪声且样本可能不足以给出 ≤0.3% 的上界；A1 判定需要人工裁决不一致样本。
2. **中文口语/超短句本质上有歧义**：覆盖率可能显著低于 60%；是否能同时满足 A1=0 与 B2≥60% 没有文献可借鉴（**[推测]**）。
3. **Jev 在大 state 与顺序偏置下的真实表现**（文档自认有 context rot 与靠前偏好），以及中文校准，目前只有 12 条合成样例。
4. **闸门的非独立性**：多模型一致/多顺序一致在强模型上会“一致地错”，增量必须靠 D5 实测，不能假设。
5. **模型能力未验证**：§6 的模型是列表数据，我无法在此确认其中文/选择任务能力，也未测时延。

### 数据质量问题（对 TE-4b 的提醒）

1. **时间切分把"工具使用习惯"也切开了**：dev 的续接样本 97% 来自 Codex（363/376），held-out 55% 来自 Claude（139/252）。原因是 Claude 默认只保留 30 天且用户近期才转向 Claude；dev 上定的阈值/提示词能否迁移到 Claude 为主的 held-out 要打问号。基线在 Claude 样本上的澄清前 3 命中（17.7%）明显低于 Codex（35.0%）。建议 TE-4b 汇报时按 provider 拆开，并在 dev 内再切一份 Claude 子集做阈值检查。
2. **召回是头号问题**：生产 FTS 取前 12，续接样本里正确会话在其中的比例 dev 59%、held-out 45%；澄清前 3 命中率因此只有 25–46%，远低于 ≥95% 的门槛。D3（召回对比）应排在 D4 之前，因为后面的模型再强，候选里没有答案就只会送错或澄清。
3. **NEW 标签很软**：同项目里反复开同类任务、重复首句十分常见，"续进旧会话"在这些情形下人也未必判错。已单列 `A1 NEW` 与 `exact-repeat-of-earlier` 标签，建议门槛判定以续接标签的 A1 为主、NEW 标签的 A1 作为必须解释的第二指标，而不是混在一起。
4. **续接标签也有噪声**：间隔 ≥30 分钟只说明用户隔了一阵才回来，不保证输入"一定是对该会话说的"（也可能原本想新开但习惯性敲在当前会话）。无法自动消除，只能靠样本量摊薄。
5. **Codex 会话没有标题**（标题在 Codex 的 sqlite 里），评测卡片的 Codex `title` 一律为 null；Claude 的 `ai-title` 带时间位置。若 TE-1 能读到 Codex 线程名，D2（会话表示）的消融要包含它。
6. **现有历史里的自动化占比极高**：1445 个子代理、314 个 Jev 自己的会话、205 个纯自动化会话，若不排除，评测集会被机器输入淹没。排除规则在 `parse.mjs`，TE-1 的 `listSessions` 应使用同一口径。
7. 留出集冻结后原生文件仍在增长（含运行中的会话），因此挖掘有固定截止时间 `until`；重挖得到的留出集若与冻结值不同会被拒绝。

### 对 TE-4b 的建议

- 接入 TE-1 的生产卡片构建时只需 `setCardBuilder(fn)`（签名 `(provider, sessionFile, asOfIso) => SessionCard|null`），其余不变；换实现后先跑 `route-eval:contracts` 与 `route-eval:audit`，再用新的策略版本号跑 dev。
- Router 可以在返回值里附带 `candidates`（有序 id 列表，`provider:sessionId`）以得到 recall@k，附带 `raw: { choice, confidence }`（阈值前的首选）以得到风险-覆盖曲线。
- 每个实验用新的 `version`；留出集每个版本只能跑一次，建议只对最终候选方案跑，且先在 dev 上用风险-覆盖定好阈值（D7）。
- 优先级：先做 D3 召回（把全部近期卡片给强模型 vs FTS vs 向量），再做 D5 置信信号；基线的单模型自报概率在 dev 上不能分开对错。

| held-out | 252 | 61 | 111 |

**本机续接例上限**：全库在 30 分钟阈值下 628 条续接（10 分钟 951 条），分布在约 140 个去重会话里；Claude 近一个月只有 152 条（13 dev + 139 held-out）。TE-4a 估计"证明 A1≤0.3% 需约 1000 个自动决策、约 1700 条留出查询"，本机数据**远不够**：即便全部续接都进留出集、且自动率 100%，也只有 951 条，而基线自动率只有 13%。结论：A1=0 的统计验收在本机历史上无法完成，只能报告"零事件时的 95% 上界 = 3/自动决策数"（例如 48 个自动决策 → 约 6%），并靠使用增长或合成难例扩充；不降低质量凑数。

**"正确答案不在库"（D1）**：构造上，留出集每条续接样本的目标会话都在候选池里（审计：目标缺失 0）。真正的缺口在样本之外，用 `~/.claude/history.jsonl`（Claude 的输入历史，不随转录清理，最早 2026-04-15）与 `~/.codex/history.jsonl` 交叉核对：
- Claude：窗口内（2026-08-29 起有活动）的 479 个会话里，38 个（7.9%）在 history 里有输入但已没有转录文件（被 30 天清理或未落盘），这类会话**无法被 resume，也不在库**；364 个有转录但被排除规则排除（绝大多数是 Jev/SDK/后台会话的 tmp 探针，真实 cwd 的 bg 会话仅 6 个），77 个纳入。窗口之前的 463 个会话（501 个无转录中的大部分）同样不可恢复，说明"超期会话找不回"是真实存在、占比不小的失败来源，应作为已知限制向用户明示。
- Codex：history 里 157 个会话，只有 2 个没有转录文件（Codex 保留完整，含归档）；43 个被排除（其中 Jev 自己和 tmp 探针 39 个，真实 cwd 的 `codex-tui` 3 个）。排除规则误杀的上限因此很低，但这 3 个真实 cwd 的 `codex-tui` 排除（无真人输入）未逐个人工核对。

## 实验与 Router v2（TE-4b）

日期 2026-10-13。只含聚合数字与不含原文的类别描述；逐条结果在本机 `.runtime/route-eval/v2/`（不提交）。

### 结论

1. **召回已不是问题**：每条查询的候选池平均 74 个会话（Claude 133、Codex 41）。只按最近活跃排序，前 10 个命中 97.3%、前 20 个 99.6%、前 30 个 100%；旧的 FTS12 前 10 个只有 67.2%。生产召回改为"最近活跃前 20 ∪ 词面前 20 ∪ 上一句去处"。
2. **决定准确率的是模型档位**：便宜模型首选只有 54–66%，多模型一致也压不住高置信的错误；Opus / Sonnet 首选约 72–77%、前 3 约 91–98%。
3. **"无内容短句"是高置信送错的主要来源**：开发集上"好，开始吧""继续，做完为止"这类只有指令、没有对象的话被三个模型一致地、以 ≥0.8 置信送进别的项目。生产闸门对去掉标点后 ≤12 字或只由泛化词组成的输入一律不自动。
4. **历史"新建"标签很软**：开发集里大部分"标签是新建、模型却续接"的样本，是同项目同主题的合理续接（例如新会话的第一句提到某个文件继续排查，而同项目旧会话的第一句正是这个文件）。用户当时新开，是因为没有路由器。因此"自动送错"按类型拆开报告：硬送错（标签是会话 A、送进了会话 B）、新建标签被续进他项目、新建标签被续进同项目（软）。
5. **选定策略** `v2.0-opus-cli-t0.9-noshort`（提交 3183772）：召回如上；决策用 Opus，经本机 `claude -p --safe-mode`（复用用户已登录的 Claude Code，不需要 API key；`JEV_ROUTER_BACKEND=openrouter` 可切到 OpenRouter）；仅当置信度 ≥0.9 且输入有实际内容时自动，其余列前 3 个候选、预选第 1 个、回车确认。

## Router v3：项目优先（2026-10-19）

### 为什么换目标

用户 2026-10-19 重述初衷：想要的是一句话落到**对的项目目录**——那里有 CLAUDE.md、记忆和全部历史会话，续哪个会话可以按需；统一入口之后再接 IM、语音等入口层。再看真实入口日志（本机 `~/.jev/entry-log.jsonl`，24 条，2026-10-17 起）：经路由的 13 次里 12 次 clarify、1 次自动，时延 p50 5.0 s / p90 11.8 s；其余 11 次是用户按 ← 直接选历史会话。v2 的会话级自动送达在真实使用里几乎没有发生。

### 数据

原 `.runtime/route-eval/` 随旧 worktree 回收，已不在本机。按 `mine2.mjs` 从原生历史重挖（截止 2026-10-19T09:17Z，Claude 只保留 30 天）：候选池 235 个会话（Claude 92、Codex 143）；dev 433 条（续接 287、新建 146）；held-out 253 条（续接 187、新建 91 中可评的部分），sha256 `cc9eb881…`，冻结。与 2026-10-13 的集合不同，不可直接比较。

### 确定性规则在开发集上的表现（不调模型，`lab/exp-project.mjs`）

| 规则 | 结果 | 结论 |
|---|---|---|
| 句子里出现项目目录名（完整、唯一） | 覆盖 7.2%，命中后正确 48% | 不可用：很多目录名是两三个字的中文通用词，句子里出现同样的词并不指向那个目录 |
| 项目级 BM25 top1 | 39.8%；边际 ≥2 时覆盖 21%、正确 79% | 不足以单独自动 |
| 最近活跃项目 | 41.0% | 弱先验 |
| **项目确定后，目标 = 项目内最近会话** | **90.2%**（287 条续接） | 项目内会话数中位 2，"选会话"问题基本消失 |
| 续接样本：项目内最近会话距查询 ≤24h | 93.0%；新建样本 56.2% | 用 24h 分"续接/新建"分不开，但新建→续进同项目是软错误 |

结论：**纯确定性无法可靠选项目，但项目一旦选对，会话几乎不用选。** 所以模型只做"选项目"。

### 模型选项目（dev 每 3 取 1，145 条，`lab/exp-project-llm.mjs`，经本机 `claude -p`）

项目卡片 = 目录名 · provider · 多久前活跃 · 会话数 + 最近 3 个会话各一行（标题/首句/最近一句）+ 最近会话的回复片段；最近活跃前 40 个项目（本集 100% 包含正确项目；项目数中位 24、p90 51；prompt 中位 8k 字符）。

| 模型 | 项目首选 | 续接 / 新建 | 项目前 3 | ≥0.85 自动 / 错项目 | ≥0.9 自动 / 错项目 | p50 / p95（并发 4） |
|---|---|---|---|---|---|---|
| Opus | 71.0% (103/145) | 76.5% / 59.6% | 91.0% | 37.2% (54) / 1 | 23.4% (34) / 0 | 3.7 s / 8.3 s |
| Haiku（6 条报错） | 64.7% (90/139) | 68.4% / 56.8% | 83.5% | 46.0% (64) / 11 | 33.1% (46) / 6 | 11.9 s / 45.6 s |

- Opus 在 ≥0.85 的唯一错项目：新建标签的句子被归进另一个项目。续接样本在 ≥0.85 下 0 次错项目。
- Haiku 置信度严重过度自信（≥0.9 仍 13% 错项目），且经 `claude -p` 的时延反而更长，不能作闸门模型。
- 无内容短句占 45/145 = 31%，模型只有 51% 选对项目；这类句子产品里走快路径，不进模型。
- 对照 v2 会话级（2026-10-13 同类子集）：≥0.9 自动 16%、0 送错。项目级在 ≥0.9 下自动 23%，≥0.85 下 37%。

### 选定策略 `v3.0-project-first-opus-t0.85`（`src/layers/router/v3.ts`）

- 快路径（不调模型）：无内容短句 → 5 分钟内刚从入口发过 → 续那个；否则正看着的会话 → 续它；否则列出开着的会话（不自动）。
- 模型：Opus 经 `claude -p`，只选项目或 NEW_PROJECT；项目置信度 ≥0.85 自动。
- 项目内：恰有一个开在终端里的会话 → 写进它；多个开着 → 正看着的，否则让选；都没开 → 最近会话 ≤24h 续接，否则在项目目录新建。
- 送错项目为硬错误；项目对、会话不同为软错误，不再阻止自动。
- `JEV_ROUTER=v2` 可退回会话级路由。入口日志新增 `via`（fast/model）与 `project`，用于积累真实入口数据。

### 预启动能否降时延（实测 2026-10-19）

- 冷调用（trivial prompt）：haiku 2.3 s，opus 3.0 s；评测中 Opus 单次 p50 3.7 s（并发 4）。
- `claude -p` 普通 stdin 模式在 3 s 内收不到 stdin 就放弃，不能先起进程再喂 prompt。
- `--input-format stream-json --output-format stream-json`：进程起好等待消息；预起 6 s 后写入 → 1.7 s 出结果（haiku）。可在用户按下快捷键时预起进程、按回车时写入，省掉约 1.5–2 s 启动。**未实现**，另开任务。
